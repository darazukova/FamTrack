# Учет расходов семейного бюджета
## Цель работы
Изучить основные этапы создания информационной системы. Научиться описывать её задачи, пользователей и основные функции. Получить навыки создания  Use Case диаграмм и блок-схем для наглядного представления работы системы.
## Практическая часть
## 1. Постановка задачи
### 1.1 Описание предметной области
Предметная область — семейный бюджет, в котором нужно вести учёт расходов каждого члена семьи. Для этого создаётся информационная система «FamTrack».
Система хранит информацию о расходах, категориях расходов и пользователях. Пользователь может добавлять новые расходы, просматривать историю операций, искать необходимые записи и анализировать распределение денежных средств по категориям.
Система предназначена для автоматизации ведения семейного бюджета, обеспечения контроля расходов и повышения удобства финансового планирования
### 1.2 Цели и задачи системы
    • Автоматизировать учёт расходов: хранить информацию обо всех расходах в одной системе.
    • Структурировать работу с категориями: распределять расходы по категориям, например «Продукты», «Транспорт», «Одежда», «Развлечения» и другим.
    • Анализировать расходы: получать информацию о том, на какие категории расходуется больше всего денежных средств.
    • Усовершенствовать работу пользователя: предоставить возможность добавлять, изменять и удалять информацию о финансовых операциях.
### 1.3 Пользователи системы (актеры) и их роли
    1. Родитель — основной пользователь системы. Добавляет расходы семьи, редактирует и удаляет операции, просматривает все операции семьи, просматривает общую сумму расходов, анализирует расходы по категориям.
    2. Ребенок — пользователь. Добавляет собственные расходы, указывает категорию расхода, просматривает добавленные им расходы, редактирует и удаляет свои записи.
### 1.4 Основной функционал
    • Добавление расхода — ввод суммы, даты, категории и описания расхода.
    • Просмотр операций — просмотр истории расходов.
    • Редактирование данных — изменение ранее добавленных расходов.
    • Удаление данных — удаление ошибочных или ненужных записей.
    • Просмотр расходов по категориям — определение суммы расходов по каждой категории.

### 1.5 Архитектура проекта
Мы используем трёхуровневую архитектуру. Система состоит из трёх основных частей:
    • Слой интерфейса: пользователь работает с системой через интерфейс. Здесь можно добавлять расходы, просматривать операции, выполнять поиск.
    • Слой бизнес-логики: отвечает за основные действия системы. Проверяет введённые данные, рассчитывает общие суммы расходов и выполняет операции с финансовыми записями.
    • Слой данных: хранит информацию о пользователях, расходах и категориях расходов.
